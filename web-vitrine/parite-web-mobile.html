Parité web / mobile

Comment la version web et l'application mobile restent rigoureusement identiques — mêmes cours, mêmes jeux, mêmes outils, mêmes fonctionnalités.

=

Le principe : web et mobile ne sont pas deux projets. C'est un seul et même code. La version web est un export de l'appli mobile — elle rejoue exactement le même code dans le navigateur. Le contenu ne peut donc jamais diverger.

01Une seule source, deux sorties

Tu ne maintiens qu'une base de code. Une commande d'export en tire la version navigateur ; la boutique en tire l'appli mobile. Le même dossier de contenu (les 956 chapitres, les fiches, les jeux) alimente les deux.

📦 Code source unique
Expo / React Native · 956 chapitres · 21 matières · jeux, outils, suivi
→
🌐 Version web
expo export --platform web → GitHub Pages
📱 Appli mobile
eas build → Google Play / App Store

✓ identique   ⚠️ limite du navigateur — la seule différence est une fonction (scan QR), impossible dans tous les navigateurs. Tout le reste est rigoureusement le même.

03Comment la parité se maintient toute seule

Grâce au déploiement automatique (le workflow GitHub Actions livré dans le kit), le web suit l'appli sans effort. À chaque modification :

1
Tu modifies l'appli
Un chapitre, un jeu, une correction — dans le code, comme d'habitude.
2
Tu fais git push
Un seul geste, sur ta branche de déploiement.
3
Le web se reconstruit et se republie
GitHub Actions réexporte la version web et la met en ligne automatiquement — même niveau que l'appli.

Le web ne peut donc pas « prendre du retard » sur le contenu : il est régénéré à partir du même code à chaque fois.

04À ne pas confondre : la progression entre appareils

⚠️ Parité de contenu ≠ synchro des données

Le contenu est identique partout (c'est l'objet de cette page). Mais la progression d'un élève ne voyage pas automatiquement d'un appareil à l'autre : le web garde ses données dans le navigateur, l'appli dans le téléphone. Faire suivre la progression entre appareils est un chantier séparé (par code/QR sans compte, ou par compte + cloud) — à décider seulement si tu le souhaites un jour.
