# Initiation à la programmation

Beaucoup d'objets d'aujourd'hui (robots, jeux vidéo, feux tricolores) sont
**programmés** : on leur donne à l'avance une liste d'ordres à exécuter. Apprendre
à programmer, c'est apprendre à **donner des ordres précis à une machine** pour
qu'elle fasse ce qu'on veut.

## L'algorithme : une suite d'instructions

Un **algorithme** est une **suite d'instructions**, données **dans l'ordre**,
pour réaliser une tâche. C'est un peu comme une **recette de cuisine** : on suit
les étapes une par une, dans le bon ordre.

Une **instruction** est **un ordre**, une seule action à faire (« avance de
10 pas », « tourne à droite »). La machine exécute les instructions **les unes
après les autres**.

> L'ordre compte ! « Mets tes chaussettes puis tes chaussures » ne donne pas le
> même résultat que l'inverse. Une machine fait **exactement** ce qu'on lui dit,
> dans l'ordre indiqué.

## Programmer avec des blocs (Scratch)

Au collège, on programme souvent avec un logiciel comme **Scratch**. On assemble
des **blocs** d'instructions comme des pièces de puzzle, sans écrire de texte
compliqué. Un personnage à l'écran, le **lutin**, exécute les blocs : il avance,
tourne, dit quelque chose, change de couleur…

## La séquence : les instructions à la suite

La **séquence** est l'enchaînement des instructions **les unes après les
autres**, dans l'ordre. C'est la base d'un programme : la machine lit la première
instruction, puis la deuxième, et ainsi de suite.

## La boucle : répéter sans tout réécrire

Une **boucle** sert à **répéter** plusieurs fois une ou plusieurs instructions,
sans les réécrire à chaque fois. Pour dessiner un carré, au lieu d'écrire
« avance, tourne » quatre fois, on écrit :

**Répéter 4 fois : [ avance de 100 ; tourne de 90° ]**

La boucle rend le programme plus **court** et plus **clair**.

## La condition : faire un choix (si… alors…)

Une **condition** permet à la machine de **choisir** quoi faire selon une
situation. On l'écrit avec **« si… alors… »** :

**Si** le lutin touche le bord, **alors** il rebondit.

La machine **teste** si la condition est vraie. Si oui, elle fait l'action ; si
non, elle ne la fait pas (ou fait autre chose avec « sinon »). C'est ce qui permet
à un objet de **réagir** à ce qui se passe.

## Un lien avec les objets techniques

Dans un objet programmé, la condition utilise souvent un **capteur** : « **si**
le capteur détecte un obstacle, **alors** le robot s'arrête ». Le programme
commande alors un **actionneur** (le moteur). Programmer, c'est écrire la **chaîne
d'information** de l'objet.

## Ce qu'il faut retenir

- Un **algorithme** est une **suite d'instructions dans l'ordre** pour réaliser
  une tâche.
- Une **instruction** est un ordre unique ; la machine les exécute **dans
  l'ordre**.
- La **séquence** enchaîne les instructions les unes après les autres.
- Une **boucle** sert à **répéter** des instructions sans les réécrire.
- Une **condition** (**si… alors…**) permet de **choisir** une action selon une
  situation, souvent grâce à un **capteur**.

## Les erreurs à éviter

- **Croire que l'ordre des instructions n'a pas d'importance.** La machine
  exécute exactement dans l'ordre donné : le résultat change si on inverse.
- **Confondre boucle et condition.** La boucle **répète** ; la condition
  **choisit** (si… alors…).
- **Penser que la machine « devine » ce qu'on veut.** Elle fait uniquement ce
  qu'on a écrit, sans deviner.
- **Oublier d'écrire toutes les étapes.** Un algorithme doit décrire chaque
  action, même celles qui semblent évidentes.
